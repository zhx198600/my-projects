### Context 主要结构

#### 状态定义 (`ApprovalState`)
```typescript
{
  applications: Application[];   // 申请列表
  currentRole: Role;              // 当前角色，默认 'department_manager'
}
```

#### Action 类型
| Action | 说明 |
|--------|------|
| `SET_ROLE` | 切换角色 |
| `CREATE_APPLICATION` | 创建新申请（添加到数组开头） |
| `APPROVE_APPLICATION` | 同意申请 |
| `REJECT_APPLICATION` | 驳回申请 |
| `CC_APPLICATION` | 抄送申请 |

#### 核心方法
| 方法 | 说明 |
|------|------|
| `switchRole(role: Role)` | 切换当前角色 |
| `getApplicationsByRole()` | 根据当前角色过滤可见申请 |
| `approveApplication(appId, comment)` | 同意指定申请 |
| `rejectApplication(appId, comment)` | 驳回指定申请 |
| `ccApplication(appId, roles)` | 抄送申请给多个角色（去重） |
| `createApplication(input)` | 创建新申请 |
| `getApplicationById(appId)` | 根据 ID 查找申请 |

---

### 角色过滤逻辑实现说明

**核心逻辑**位于 [ApprovalContext.tsx:177-207](e:\workspace\trace\my-projects\project14\src\contexts\ApprovalContext.tsx#L177-L207)：

```
角色与 Order 映射：
department_manager → 1
finance → 2
general_manager → 3
```

**过滤规则**（按优先级）：

1. **抄送的申请始终可见** - 只要角色在 `ccRoles` 中，无论状态如何都能看到

2. **部门经理 (order=1)** - 可以看到**所有**状态的申请（无过滤）

3. **其他角色（财务/总经理）**：
   - `completed` 状态的申请 **可见**
   - `pending` 状态：`currentNodeOrder >= currentOrder`（当前节点顺序达到或超过角色的 order）
   - `rejected` 状态：`rejectedNode >= currentOrder`（驳回节点达到或超过角色的 order）

**实际效果**：
- **财务** 看不到：部门经理待审批 (`currentNodeOrder=1, status=pending`)、部门经理已驳回 (`rejectedNode=1`)
- **总经理** 看不到：部门经理阶段、财务阶段的待审批或已驳回申请

## 主要实现说明

### 1. Toast 提示组件 (`Toast.tsx`)
- **类型支持：** success（绿色背景、成功图标）和 error（红色背景、错误图标）
- **自动消失：** 3秒后自动关闭
- **手动关闭：** 点击右上角 X 图标可关闭
- **动画效果：** 从屏幕右上角滑入/滑出（使用 CSS transition）
- **单例模式：** 通过 Context 状态管理确保同一时间只显示一个 Toast

### 2. Toast Context (`ToastContext.tsx`)
- **状态管理：** 使用 useState 管理 Toast 的消息、类型和可见性
- **API 设计：** 提供 `showToast(message, type)` 方法
- **Provider 模式：** ToastProvider 包裹应用，同时渲染 Toast 组件

### 3. ApprovalContext 集成 Toast
- **架构设计：** ToastProvider 在外层包裹 ApprovalProvider，确保 ApprovalProvider 可以使用 useToast
- **操作提示：** 在以下操作后显示成功 Toast：
  - `approveApplication` → "审批成功"
  - `rejectApplication` → "驳回成功"
  - `ccApplication` → "抄送成功"
  - `createApplication` → "申请创建成功"

   - 部门经理 → 财务 → 总经理，逐级审批

3. **核心审批操作**
   - **同意**：推进流程到下一节点
   - **驳回**：流程结束，状态变为"已驳回"
   - **抄送**：将申请抄送给其他角色

4. **发起新申请**
   - 表单包含：标题（必填）、金额（必填）、说明（可选）
   - 表单验证：标题非空、金额为正数

# 流程编排平台 - Product Requirement Document

## Overview
- **Summary**: 构建一个纯前端的流程编排平台第一版，支持三个审批节点（部门经理、财务、总经理）的串行审批流程，提供角色模拟、流程查看和审批操作功能。
- **Purpose**: 为企业审批场景提供一个可视化的流程编排和执行平台，支持标准审批操作（同意、驳回、抄送）。
- **Target Users**: 需要模拟审批流程的测试人员、产品经理和业务人员。

## Goals
- 实现三节点串行审批流程（部门经理 -> 财务 -> 总经理）
- 支持角色模拟切换功能
- 提供流程发起、查看和审批操作界面
- 实现核心审批操作：同意、驳回、抄送
- 所有数据本地mock，不依赖后端服务

## Non-Goals (Out of Scope)
- 不支持自定义节点配置
- 不支持并行审批模式
- 不支持用户认证和登录系统
- 不支持流程数据持久化（刷新页面数据重置）
- 不支持复杂的条件分支

## Background & Context
- 这是一个MVP版本，旨在验证流程编排平台的核心概念
- 采用纯前端React应用架构，所有数据在前端内存中mock
- 串行审批流程：申请发起 -> 部门经理审批 -> 财务审批 -> 总经理审批

## Functional Requirements
- **FR-1**: 角色模拟系统
  - 支持三种角色：部门经理、财务、总经理
  - 支持角色切换查看
  - 每个角色只能看到和操作自己节点的审批任务

- **FR-2**: 流程列表展示
  - 展示所有申请流程列表
  - 显示流程当前状态（待审批、已同意、已驳回、已完成）
  - 显示当前审批节点位置

- **FR-3**: 流程详情查看
  - 展示完整流程节点和流转状态
  - 显示每个节点的审批记录和意见
  - 可视化展示流程进度

- **FR-4**: 审批操作
  - **同意**: 当前节点同意，流程进入下一节点
  - **驳回**: 当前节点驳回，流程结束或返回发起节点
  - **抄送**: 抄送给其他角色（只读查看）

- **FR-5**: 发起申请
  - 创建新的审批申请
  - 填写申请标题、金额、说明等基本信息
  - 申请提交后自动进入部门经理审批节点

- **FR-6**: Mock数据管理
  - 提供示例mock数据用于演示
  - 支持添加新的mock申请
  - 模拟流程流转时的数据更新

## Non-Functional Requirements
- **NFR-1**: 界面响应
  - 页面加载时间 < 2秒
  - 操作响应时间 < 500ms
- **NFR-2**: 兼容性
  - 支持现代浏览器（Chrome, Firefox, Edge最新版本）
- **NFR-3**: 可维护性
  - 代码结构清晰，组件化设计
  - 类型定义完整（使用TypeScript）

## Constraints
- **Technical**: 纯前端React应用，不依赖后端服务
- **Business**: 仅限三个固定节点，第一版不支持扩展
- **Dependencies**: React 18+, 可选用UI组件库如Ant Design或Tailwind CSS

## Assumptions
- 用户了解基本的审批流程概念
- 所有数据在浏览器会话期间有效，刷新后重置
- 角色切换不需要密码验证
- 财务节点只在部门经理同意后可见
- 总经理节点只在财务同意后可见

## Acceptance Criteria

### AC-1: 角色切换功能
- **Given**: 用户打开应用
- **When**: 用户点击角色切换按钮，选择不同角色
- **Then**: 界面显示对应角色的视角和可操作任务
- **Verification**: `programmatic`
- **Notes**: 不同角色看到的任务列表应该不同

### AC-2: 流程列表展示
- **Given**: 存在多个mock申请
- **When**: 用户进入首页
- **Then**: 显示所有申请列表，包含标题、状态、当前节点、创建时间
- **Verification**: `programmatic`

### AC-3: 流程详情查看
- **Given**: 用户点击某个申请进入详情页
- **When**: 查看流程详情
- **Then**: 显示完整的审批流程节点图，各节点状态和审批意见
- **Verification**: `human-judgment`

### AC-4: 部门经理同意操作
- **Given**: 用户以部门经理角色登录，存在待审批申请
- **When**: 点击"同意"按钮并填写审批意见
- **Then**: 流程状态更新，当前节点标记为已同意，流程推进到财务节点
- **Verification**: `programmatic`

### AC-5: 部门经理驳回操作
- **Given**: 用户以部门经理角色登录，存在待审批申请
- **When**: 点击"驳回"按钮并填写驳回意见
- **Then**: 流程状态标记为"已驳回"，流程结束，不再继续推进
- **Verification**: `programmatic`

### AC-6: 财务节点可见性
- **Given**: 用户以财务角色登录
- **When**: 查看待审批任务
- **Then**: 只能看到部门经理已经同意的申请，未到财务节点的申请不可见
- **Verification**: `programmatic`

### AC-7: 总经理节点可见性
- **Given**: 用户以总经理角色登录
- **When**: 查看待审批任务
- **Then**: 只能看到财务已经同意的申请，部门经理阶段的申请不可见
- **Verification**: `programmatic`

### AC-8: 流程完成
- **Given**: 部门经理、财务、总经理全部同意
- **When**: 最后一个节点（总经理）点击同意
- **Then**: 流程状态标记为"已完成"，所有节点显示已同意
- **Verification**: `programmatic`

### AC-9: 抄送功能
- **Given**: 用户在任意审批节点
- **When**: 执行抄送操作，选择抄送给其他角色
- **Then**: 被抄送的角色可以在"抄送我"列表中看到该申请，但无法进行审批操作
- **Verification**: `programmatic`

### AC-10: 发起新申请
- **Given**: 用户在首页
- **When**: 点击"发起申请"，填写标题、金额、说明后提交
- **Then**: 新申请出现在列表中，状态为"待审批"，当前节点为部门经理
- **Verification**: `programmatic`

## Open Questions
- [ ] 驳回后流程是直接结束还是返回发起人修改后重新提交？（当前假设直接结束）
- [ ] 金额字段是否需要特殊处理，如超过一定金额直接跳转到总经理？（当前假设固定串行）
- [ ] 是否需要审批时限和提醒功能？（当前第一版不考虑）

# OPPO 工单管理系统 - Product Requirement Document

## Overview
- **Summary**: 开发一个 OPPO 工单管理系统，支持七类工单的新建、查看、编辑和详情查看功能。系统采用单角色（超级管理员）设计，登录页面直接选择角色登录。
- **Purpose**: 为 OPPO 提供一个统一的工单管理平台，用于处理用户投诉、故障返修、建议、报表问题、平台功能异常、检测、预约上门服务等各类用户请求。
- **Target Users**: 超级管理员（系统运维人员、客服人员、技术支持人员）

## Goals
- 实现七类工单的完整生命周期管理
- 提供统一的工单公共字段管理
- 支持各类型工单的自定义字段配置
- 实现工单的新建、列表查看、编辑及详情查看功能

## Non-Goals (Out of Scope)
- 多用户角色权限管理（仅支持超级管理员单角色）
- 工单流转工作流（状态自动流转）
- 工单统计分析报表
- 消息通知系统
- 移动端适配

## Background & Context
- 系统基于 Python Django 框架开发，使用 SQLite 作为数据库
- 前端采用 Django 自带的模板系统或简单的 HTML/CSS/JS
- 采用单角色设计，简化权限管理

## Functional Requirements

### FR-1: 用户认证与登录
- 登录页面展示角色选择（仅超级管理员）
- 登录后进入系统首页
- 无需用户名密码，直接选择角色登录（简化设计）

### FR-2: 工单类型管理
- 支持七类工单：投诉、故障返修、建议、报表问题、平台功能异常、检测、预约上门服务
- 每种工单类型可配置独立的自定义字段

### FR-3: 公共字段管理
- 工单类型
- 工单来源（电话、网站、APP、微信、线下）
- 工单状态（待受理、处理中、已解决、已关闭）
- 紧急程度（低、中、高、紧急）
- 用户姓名
- 用户联系方式（电话、邮箱）
- 受理人
- 处理人
- 处理部门
- 转派记录（记录转派历史）
- 创建时间
- 更新时间

### FR-4: 自定义字段管理
- 每种工单类型可配置自定义字段
- 字段控件类型支持：输入框、下拉框、文本域
- 支持字段配置：字段名、控件类型、是否必填、选项（下拉框时）

### FR-5: 工单新建功能
- 根据工单类型展示对应的表单（公共字段 + 自定义字段）
- 表单验证（必填项、格式验证）
- 提交后保存工单数据

### FR-6: 工单列表查看
- 展示所有工单列表
- 支持按工单类型、状态、紧急程度筛选
- 支持按创建时间排序
- 列表字段：工单编号、工单类型、用户姓名、联系方式、状态、紧急程度、创建时间、操作

### FR-7: 工单编辑功能
- 可编辑工单的所有字段
- 记录转派历史（当处理人/处理部门变更时）
- 保存编辑历史

### FR-8: 工单详情查看
- 展示工单完整信息（公共字段 + 自定义字段）
- 展示转派记录历史
- 展示编辑历史

## Non-Functional Requirements

### NFR-1: 性能要求
- 页面加载时间 < 2 秒
- 工单列表查询时间 < 1 秒

### NFR-2: 安全性
- 登录会话管理
- SQL 注入防护（Django ORM 自动处理）
- XSS 防护（Django 模板自动转义）

### NFR-3: 可维护性
- 代码结构清晰，模块化设计
- 数据库设计规范化

## Constraints

- **Technical**: 
  - Python 3.8+
  - Django 4.2+
  - SQLite 数据库
- **Business**: 
  - 单一角色设计，无需复杂权限管理
- **Dependencies**: 
  - Django 框架及依赖包

## Assumptions

- 用户登录后拥有所有权限（超级管理员）
- 工单状态变更由管理员手动操作
- 转派记录仅在处理人/处理部门变更时记录

## Acceptance Criteria

### AC-1: 登录功能
- **Given**: 用户访问登录页面
- **When**: 用户选择"超级管理员"角色并点击登录
- **Then**: 成功进入系统首页
- **Verification**: `programmatic`

### AC-2: 工单类型配置
- **Given**: 系统初始化完成
- **When**: 查看工单类型配置
- **Then**: 存在七类工单类型：投诉、故障返修、建议、报表问题、平台功能异常、检测、预约上门服务
- **Verification**: `programmatic`

### AC-3: 公共字段完整性
- **Given**: 新建任意类型工单
- **When**: 查看表单字段
- **Then**: 包含所有公共字段：工单类型、工单来源、工单状态、紧急程度、用户姓名、用户联系方式、受理人、处理人、处理部门、转派记录
- **Verification**: `programmatic`

### AC-4: 自定义字段配置
- **Given**: 为某工单类型配置自定义字段
- **When**: 新建该类型工单
- **Then**: 表单显示配置的自定义字段，控件类型正确（输入框/下拉框/文本域）
- **Verification**: `programmatic`

### AC-5: 工单新建
- **Given**: 用户填写完整的工单表单
- **When**: 点击提交
- **Then**: 工单成功保存，生成唯一工单编号，跳转到工单列表或详情页
- **Verification**: `programmatic`

### AC-6: 工单列表筛选
- **Given**: 存在多类型多状态的工单
- **When**: 按工单类型、状态、紧急程度筛选
- **Then**: 列表只显示符合筛选条件的工单
- **Verification**: `programmatic`

### AC-7: 工单编辑
- **Given**: 打开某工单的编辑页面
- **When**: 修改字段值并保存
- **Then**: 工单信息更新，编辑历史被记录
- **Verification**: `programmatic`

### AC-8: 转派记录
- **Given**: 编辑工单时修改处理人或处理部门
- **When**: 保存修改
- **Then**: 转派记录被创建，包含变更前/后的值、操作时间
- **Verification**: `programmatic`

### AC-9: 工单详情查看
- **Given**: 点击某工单的详情链接
- **When**: 查看详情页面
- **Then**: 完整显示公共字段、自定义字段、转派记录、编辑历史
- **Verification**: `programmatic`

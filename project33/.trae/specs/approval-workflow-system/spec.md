# 高校审批流管理系统 - Product Requirement Document

## Overview

- **Summary**: 开发一个面向高校场景的可视化审批流管理系统，支持拖拽式流程设计、组织架构适配、表单权限控制、全流程审批追溯，可快速搭建学生请假、调课申请、经费报备、校园报修等常用审批流程。
- **Purpose**: 解决高校传统审批流程繁琐、效率低下、追溯困难的问题，提供灵活可配置的流程化管理平台，实现审批流程数字化、标准化、可视化。
- **Target Users**: 高校信息化管理员、各部门行政人员、教师、学生、各级领导

## Goals

- 提供可视化拖拽的流程设计器，支持流程节点编排和连线配置
- 实现完整的高校组织架构体系，支持按部门、岗位、角色、上下级配置审批人
- 实现业务表单与流程绑定，各节点可独立配置字段查看/编辑权限
- 提供完整的审批核心功能：同意、驳回、转交、抄送、流程日志
- 预置高校常用流程模板：学生请假、调课申请、经费报备、校园报修
- 实现审批全程可追溯，数据统一流转

## Non-Goals (Out of Scope)

- 不包含复杂的BPMN 2.0标准规范实现，聚焦高校常用场景
- 不实现移动端原生APP，提供响应式Web端支持
- 不包含即时通讯功能，审批通知通过系统消息和邮件实现
- 不实现高校财务系统对接，仅做流程层面的经费报备审批
- 不实现第三方统一身份认证对接，基础版本内置用户体系

## Background & Context

- 高校审批场景具有角色多样（学生、教师、辅导员、部门负责人、分管领导等）、组织架构层级复杂的特点
- 传统纸质审批或简单OA系统难以灵活适应高校多样化的审批需求
- 现有审批系统往往流程固定，无法让业务部门自主配置和调整流程
- 技术栈：Next.js 14 (React) + TypeScript + Node.js (NestJS) + SQLite + Ant Design

## Functional Requirements

- **FR-1**: 可视化流程设计器，支持拖拽新增节点、连线编排
- **FR-2**: 支持串行、分支（条件）流转逻辑配置
- **FR-3**: 完整的高校组织架构管理，包含学院、部门、岗位
- **FR-4**: 审批节点人员配置，支持按部门、岗位、角色、上下级、指定人员选择
- **FR-5**: 业务表单设计，支持常用字段类型（文本、选择、日期、附件等）
- **FR-6**: 流程与表单绑定，各节点独立配置字段查看、编辑权限
- **FR-7**: 审批核心操作：同意、驳回（可指定驳回节点）、转交、抄送
- **FR-8**: 流程执行日志，完整记录每个节点的审批时间、人员、意见、操作
- **FR-9**: 预置高校常用流程模板库，支持一键启用和修改
- **FR-10**: 我的待办、我发起的、我审批的流程列表管理
- **FR-11**: 用户角色权限管理：超级管理员、流程管理员、普通用户

## Non-Functional Requirements

- **NFR-1**: 流程设计器操作响应时间 < 100ms
- **NFR-2**: 表单数据加载时间 < 500ms
- **NFR-3**: 支持至少1000并发用户在线使用
- **NFR-4**: 数据持久化，所有审批数据和操作日志永久保存
- **NFR-5**: 页面响应式设计，支持PC和Pad端访问
- **NFR-6**: 代码模块化设计，便于后续功能扩展
- **NFR-7**: API接口RESTful设计规范，统一返回格式和错误处理

## Constraints

- **Technical**: Next.js 14 + TypeScript + NestJS + PostgreSQL + Ant Design
- **Business**: 聚焦高校场景，预置角色和模板需符合国内高校通用组织架构
- **Dependencies**: 需集成React Flow实现可视化流程设计，需集成表单设计器

## Assumptions

- 用户具备基本的计算机操作能力，能够理解流程设计的基本概念
- 高校组织架构采用标准的校-院-部门三级架构
- 审批流转主要为串行和简单分支场景，不涉及复杂的并行、子流程
- 表单数据量在合理范围，单个流程实例附件不超过100MB

## Acceptance Criteria

### AC-1: 流程设计器拖拽功能

- **Given**: 用户进入流程设计页面
- **When**: 用户从组件库拖拽节点到画布，并进行连线
- **Then**: 节点成功添加到画布，连线成功建立，节点位置可拖拽调整
- **Verification**: `programmatic` + `human-judgment`

### AC-2: 串行流转逻辑

- **Given**: 流程配置了A→B→C三个串行节点
- **When**: A节点审批通过
- **Then**: 流程自动流转到B节点，待B审批通过后流转到C节点
- **Verification**: `programmatic`

### AC-3: 分支流转逻辑

- **Given**: 流程配置了条件分支，金额>5000走分管领导审批，否则走部门负责人审批
- **When**: 用户提交申请金额为6000元
- **Then**: 流程自动流转到分管领导审批节点
- **Verification**: `programmatic`

### AC-4: 高校角色审批人配置

- **Given**: 流程节点配置审批人为"辅导员"角色
- **When**: 学生提交请假申请
- **Then**: 该学生对应的辅导员收到待办审批
- **Verification**: `programmatic`

### AC-5: 字段权限控制

- **Given**: 流程A节点配置"金额"字段为编辑权限，B节点配置为只读权限
- **When**: 审批人在B节点查看表单
- **Then**: "金额"字段显示为只读状态，无法修改
- **Verification**: `programmatic`

### AC-6: 审批驳回功能

- **Given**: 流程流转到C节点
- **When**: C节点审批人选择驳回到A节点
- **Then**: 流程回退到A节点，A节点重新收到待办
- **Verification**: `programmatic`

### AC-7: 审批转交功能

- **Given**: A节点审批人收到待办
- **When**: A节点审批人将审批转交给D用户
- **Then**: D用户收到该待办审批，原审批人不再显示待办
- **Verification**: `programmatic`

### AC-8: 流程日志记录

- **Given**: 流程经历了提交、A审批、B审批多个步骤
- **When**: 用户查看流程详情
- **Then**: 完整显示每个节点的操作人、操作时间、审批意见、操作类型
- **Verification**: `programmatic`

### AC-9: 流程模板库使用

- **Given**: 系统预置了"学生请假"流程模板
- **When**: 管理员选择启用该模板
- **Then**: 完整的请假流程和对应表单自动创建，可直接使用
- **Verification**: `programmatic`

### AC-10: 待办事项提醒

- **Given**: 用户有新的待办审批
- **When**: 用户登录系统
- **Then**: 待办数量在首页醒目显示，待办列表按时间排序展示
- **Verification**: `human-judgment`

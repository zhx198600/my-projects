# 在线客服聊天机器人网站 - 产品需求文档

## Overview
- **Summary**: 构建一个在线客服聊天机器人网站，包含客户端和客服端。客户端用于用户发起咨询，机器人根据知识库自动回复；客服端用于管理知识库内容。
- **Purpose**: 提供一个自动化的客服聊天系统，减少人工客服工作量，快速响应客户咨询。
- **Target Users**: 
  - 客户（客户端）：需要咨询产品或服务问题的用户
  - 客服管理员（客服端）：负责维护知识库内容的运营人员

## Goals
- 客户可以通过客户端发起实时对话咨询
- 聊天机器人能根据知识库自动识别客户意图并回复
- 客服管理员可以通过客服端管理知识库（增删改查）
- 客服管理员可以查看历史对话记录

## Non-Goals (Out of Scope)
- 不支持多轮对话的复杂上下文理解
- 不集成第三方 AI 模型（如 GPT），使用关键词匹配实现
- 不支持实时人工客服接入，仅支持机器人自动回复
- 不支持图片、文件等多媒体消息，仅支持文本

## Background & Context
- 这是一个全新的项目，从空白开始构建
- 技术栈已确认：
  - 前端：React + TypeScript + Vite
  - 后端：Node.js + Express + TypeScript
  - 数据存储：SQLite
  - 意图识别：关键词匹配

## Functional Requirements

### FR-1: 客户端功能
- **FR-1.1**: 用户可以打开聊天窗口，输入用户名开始对话
- **FR-1.2**: 用户可以发送文本消息，接收机器人回复
- **FR-1.3**: 聊天记录在会话期间保持可见，新消息自动滚动到底部
- **FR-1.4**: 显示消息发送状态（发送中/已发送）

### FR-2: 聊天机器人功能
- **FR-2.1**: 接收用户消息，进行关键词匹配识别意图
- **FR-2.2**: 根据匹配到的意图，从知识库中获取对应的回复话术
- **FR-2.3**: 当未匹配到任何意图时，返回默认兜底回复
- **FR-2.4**: 支持多关键词匹配，返回匹配度最高的回复

### FR-3: 知识库管理功能
- **FR-3.1**: 客服管理员可以查看所有知识库条目列表
- **FR-3.2**: 客服管理员可以添加新的知识库条目（问题、关键词、回复）
- **FR-3.3**: 客服管理员可以编辑现有的知识库条目
- **FR-3.4**: 客服管理员可以删除不需要的知识库条目
- **FR-3.5**: 支持按关键词或问题搜索知识库

### FR-4: 对话记录功能
- **FR-4.1**: 系统自动记录所有对话内容（用户消息、机器人回复、时间戳）
- **FR-4.2**: 客服管理员可以查看历史对话列表
- **FR-4.3**: 客服管理员可以查看具体某一次对话的详细内容

### FR-5: 数据持久化
- **FR-5.1**: 知识库内容持久化存储到 SQLite 数据库
- **FR-5.2**: 对话记录持久化存储到 SQLite 数据库
- **FR-5.3**: 应用重启后数据不丢失

## Non-Functional Requirements

- **NFR-1**: 响应性能
  - 机器人回复延迟不超过 1 秒（模拟思考时间的延迟除外）
  - 页面加载时间不超过 2 秒
- **NFR-2**: 可用性
  - 客服端应提供清晰的操作指引
  - 错误消息应该友好、可理解
- **NFR-3**: 可维护性
  - 代码结构清晰，模块化
  - 合理的目录组织，便于后续扩展

## Constraints

- **Technical**:
  - 前端必须使用 React + TypeScript + Vite
  - 后端必须使用 Node.js + Express + TypeScript
  - 数据库使用 SQLite，不需要独立部署数据库服务
- **Business**:
  - 这是一个原型/演示项目，用于验证概念
  - 优先保证核心功能可用
- **Dependencies**:
  - 需要使用 npm/yarn 包管理器
  - 浏览器必须支持 WebSocket 或长轮询（用于实时聊天）

## Assumptions

- 假设服务器和客户端在同一域名下部署，或已正确配置 CORS
- 假设用户使用现代浏览器（Chrome、Firefox、Safari 最新版本）
- 假设初始时知识库为空，需要客服管理员手动添加内容
- 假设同一时间只有一个客服管理员操作，不需要并发冲突处理

## Acceptance Criteria

### AC-1: 客户端用户可以开始对话
- **Given**: 用户访问客户端页面
- **When**: 用户输入用户名并点击"开始聊天"
- **Then**: 进入聊天界面，显示欢迎消息
- **Verification**: `programmatic`

### AC-2: 用户发送消息后机器人回复
- **Given**: 用户已进入聊天界面，知识库存在匹配的关键词
- **When**: 用户发送包含关键词的消息
- **Then**: 机器人在 1 秒内（加上模拟思考延迟）显示回复
- **Verification**: `programmatic`

### AC-3: 未匹配关键词时返回兜底回复
- **Given**: 用户已进入聊天界面，知识库没有匹配的关键词
- **When**: 用户发送消息
- **Then**: 机器人返回预设的兜底回复（如"抱歉，我暂时无法解答您的问题，请稍后再试或联系人工客服"）
- **Verification**: `programmatic`

### AC-4: 聊天记录保持滚动
- **Given**: 聊天界面有多条消息
- **When**: 新消息到达
- **Then**: 聊天区域自动滚动到最新消息
- **Verification**: `human-judgment`

### AC-5: 客服端可以查看知识库列表
- **Given**: 客服管理员访问客服端页面
- **When**: 点击"知识库管理"
- **Then**: 显示所有知识库条目列表，包含问题、关键词、回复预览
- **Verification**: `programmatic`

### AC-6: 客服端可以添加知识库条目
- **Given**: 客服管理员在知识库管理页面
- **When**: 点击"添加"，输入问题、关键词和回复内容，保存
- **Then**: 新条目出现在知识库列表中，数据库中也有记录
- **Verification**: `programmatic`

### AC-7: 客服端可以编辑知识库条目
- **Given**: 客服管理员在知识库管理页面
- **When**: 点击某条目"编辑"，修改内容后保存
- **Then**: 该条目内容已更新，数据库中同步更新
- **Verification**: `programmatic`

### AC-8: 客服端可以删除知识库条目
- **Given**: 客服管理员在知识库管理页面
- **When**: 点击某条目"删除"并确认
- **Then**: 该条目从列表中消失，数据库中也被删除
- **Verification**: `programmatic`

### AC-9: 客服端可以查看对话历史
- **Given**: 已有一些对话记录存储在数据库
- **When**: 客服管理员点击"对话记录"
- **Then**: 显示对话列表，点击某条可查看详细对话内容
- **Verification**: `programmatic`

### AC-10: 应用重启后数据不丢失
- **Given**: 数据库中已有知识库和对话记录
- **When**: 重启后端服务
- **Then**: 重新访问客服端，之前的数据仍然存在
- **Verification**: `programmatic`

## Open Questions

- [ ] 机器人回复是否需要模拟"正在输入"的状态？（建议添加，提升用户体验）
- [ ] 客户端是否需要支持多会话？（当前假设单用户单会话）

# 平面图片转3D可视化平台 - Product Requirement Document

## Overview
- **Summary**: 构建一个Web平台，允许用户上传包含单一主体的平面图片，通过AI自动识别并抠出图片中的主体，用户可对识别结果进行编辑调整，最终将2D主体转化为3D可渲染的模型，并支持一键渲染出漂亮的颜色效果。
- **Purpose**: 为设计师、创作者提供一个便捷的工具，将普通2D图片转化为3D可视化内容，降低3D创作的门槛。
- **Target Users**: 平面设计师、UI/UX设计师、创意工作者、内容创作者。

## Goals
- 提供简单易用的图片上传接口，支持多种图片格式
- 实现精准的图片主体自动识别与抠图功能
- 提供直观的主体编辑工具（调整轮廓、删除背景等）
- 集成第三方API将2D主体转化为3D模型
- 支持3D模型的交互式渲染与颜色美化
- 提供导出功能，保存3D模型或渲染结果

## Non-Goals (Out of Scope)
- 不支持同时处理多主体的复杂图片（仅支持单一主体）
- 不提供复杂的3D建模功能（仅支持2D转3D的基础转换）
- 不支持视频或动态图片的处理
- 不提供团队协作或多用户共享功能
- 不提供图片生成功能（仅处理用户上传的已有图片）

## Background & Context
- 随着3D设计和元宇宙概念的普及，越来越多的创作者需要将2D素材转化为3D内容
- 传统3D建模学习曲线陡峭，需要专业技能和工具
- 现有AI技术（图像分割、2D转3D）已经成熟，可以通过API服务快速集成
- 目标是打造一个"零门槛"的2D转3D工具，让普通设计师也能轻松创建3D内容

## Functional Requirements
- **FR-1**: 图片上传
  - 支持JPG、PNG、WebP等常见图片格式
  - 提供拖拽上传和点击上传两种方式
  - 实时显示上传进度和预览
  - 限制图片大小（建议最大10MB）
- **FR-2**: 主体自动识别
  - 调用第三方图像分割API识别图片中的主体
  - 自动提取主体轮廓，生成透明背景
  - 显示识别结果的预览
- **FR-3**: 主体编辑
  - 提供画笔/橡皮擦工具，手动调整主体边界
  - 支持撤销/重做操作
  - 提供缩放和平移功能，便于精细编辑
  - 支持实时预览编辑效果
- **FR-4**: 2D转3D转换
  - 调用第三方2D转3D API，将编辑好的2D主体转化为3D模型
  - 显示转换进度
  - 提供3D模型预览（可旋转、缩放查看）
- **FR-5**: 3D渲染与颜色美化
  - 提供"一键渲染"按钮，自动为3D模型添加漂亮的颜色和光照效果
  - 支持切换不同的渲染风格（如写实、卡通、赛博朋克等）
  - 实时显示渲染效果
- **FR-6**: 结果导出
  - 支持导出3D模型（如GLB/GLTF格式）
  - 支持导出渲染后的图片（PNG/JPG）
  - 支持保存项目进度，方便后续编辑

## Non-Functional Requirements
- **NFR-1**: 性能
  - 页面加载时间 < 2秒
  - 图片上传响应时间 < 5秒（10MB图片）
  - 主体识别时间 < 10秒
  - 2D转3D转换时间 < 30秒
  - 3D渲染时间 < 5秒
- **NFR-2**: 可用性
  - 界面简洁直观，无需培训即可使用
  - 响应式设计，支持桌面端（优先）和平板
  - 提供清晰的错误提示和操作反馈
- **NFR-3**: 兼容性
  - 支持Chrome、Firefox、Safari、Edge最新两个版本
  - 3D渲染使用Three.js等标准WebGL库
- **NFR-4**: 安全性
  - 用户上传的图片仅用于本次处理，处理完成后可选择删除
  - 不存储用户的API密钥等敏感信息在前端
  - 使用HTTPS加密传输

## Constraints
- **Technical**: 
  - 前端使用 React 框架
  - 后端使用 Node.js + Express
  - 3D渲染使用 Three.js
  - 图像分割和2D转3D依赖第三方API服务
- **Business**: 
  - 初始版本为MVP，核心功能优先
  - 考虑后续添加付费订阅模式（高级API调用额度）
- **Dependencies**: 
  - 第三方图像分割API（如 Remove.bg、Cloudinary、或其他图像分割服务）
  - 第三方2D转3D API（如 Luma AI、Tripo3D、或其他2D转3D服务）
  - Three.js 用于前端3D渲染

## Assumptions
- 用户上传的图片确实只包含一个明显的主体
- 第三方API服务稳定可用
- 用户了解基本的图片编辑操作（缩放、画笔等）
- 浏览器支持WebGL用于3D渲染
- 项目以MVP形式启动，后续可根据用户反馈迭代

## Acceptance Criteria

### AC-1: 图片上传功能
- **Given**: 用户访问平台首页
- **When**: 用户拖拽一张JPG/PNG图片到上传区域，或点击选择文件上传
- **Then**: 图片成功上传并显示预览，上传进度条正常显示，上传完成后自动进入下一步
- **Verification**: `programmatic`
- **Notes**: 验证多种图片格式和大小限制

### AC-2: 主体自动识别
- **Given**: 用户已成功上传一张包含单一主体的图片
- **When**: 系统自动调用图像分割API进行主体识别
- **Then**: 系统显示识别结果，主体被准确抠出，背景变为透明，用户可预览效果
- **Verification**: `human-judgment` + `programmatic`
- **Notes**: 程序验证API调用成功，人工验证识别质量

### AC-3: 主体编辑功能
- **Given**: 用户已看到自动识别的主体结果
- **When**: 用户使用画笔工具添加区域，或使用橡皮擦工具删除区域，并可撤销/重做
- **Then**: 主体边界实时更新，编辑操作可撤销/重做，缩放和平移功能正常工作
- **Verification**: `programmatic`
- **Notes**: 验证编辑操作的即时反馈和历史记录功能

### AC-4: 2D转3D转换
- **Given**: 用户对编辑后的主体满意
- **When**: 用户点击"生成3D"按钮
- **Then**: 系统调用2D转3D API，显示转换进度，完成后加载3D模型并允许用户旋转、缩放查看
- **Verification**: `programmatic`
- **Notes**: 验证API调用、进度显示、3D模型加载和交互

### AC-5: 3D渲染与颜色美化
- **Given**: 用户已获得3D模型预览
- **When**: 用户点击"一键渲染"按钮，并选择不同的渲染风格
- **Then**: 3D模型应用漂亮的颜色和光照效果，切换风格时实时更新，渲染效果美观
- **Verification**: `human-judgment` + `programmatic`
- **Notes**: 程序验证渲染API调用成功，人工验证视觉效果

### AC-6: 结果导出
- **Given**: 用户对3D模型或渲染效果满意
- **When**: 用户选择导出选项（模型或图片）
- **Then**: 系统生成对应格式的文件并提供下载链接，文件可正常打开使用
- **Verification**: `programmatic`
- **Notes**: 验证导出文件的格式完整性和可访问性

### AC-7: 性能要求
- **Given**: 用户在正常网络环境下使用
- **When**: 执行各关键操作（上传、识别、转换、渲染）
- **Then**: 各操作在NFR-1规定的时间范围内完成
- **Verification**: `programmatic`
- **Notes**: 使用性能测试验证各环节耗时
